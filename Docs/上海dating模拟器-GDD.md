# 上海 Dating 模拟器

**工作名：**《今天也在上海滑水果》

**一句话：**A dating-app simulator: swipe, match, text, and date several people at once—except everyone is an adult fruit living in Shanghai.

**中文介绍：**在上海的交友软件里滑水果、同时谈几段——人是果，每次右滑也要结果。

**状态：**网页可玩原型开发中。本文已并入 `Docs/decisions/` 全部决定，后定覆盖先定。已接入不等于文案或美术定稿。

## 1. 游戏是什么

单人、文字驱动的约会模拟器。玩家在虚构水果居民使用的交友软件里滑卡、匹配、聊天、约见，同时处理多段关系，走向友情、恋爱、炮友或分开。

上海是生活环境：通勤、房租、工作、街区和婚恋市场。基调是**轻松荒诞与尖锐黑色幽默混合**；笑点来自人设与行为的反差、社交规则和生活失控。幽默禁区尚未单列。

- 水果代替人，弱化性别；角色均为成年人，性别不限制匹配或结局。
- 水果社会用**虚构族群**，通过处境、资源、通勤和社交规则影射现实；**不与现实种族一一对应**。水果参与人物与社会叙事，不只是外形替换。同种水果可以有不同性格。
- 视觉方向：仿交友软件 UI ＋**水果本体＋简化四肢**。不改成更接近人形。具体配色、服装和爱好按角色另定。桃子更骚气，部分香蕉底部剥开露一点果肉；造型可以有性暗示，亲密场景采用非露骨的淡出与事后叙事。
- 平台：对象均为虚构角色，无真人社交。电脑与手机共用同一套竖屏界面，底部四页签。当前直接打开本地 `index.html`；账号与跨设备方案未定。

## 2. 玩家循环

**滑卡 → 匹配 → 聊天／事件 → 关系选择 → 单线结局／番外；其他关系继续。**

| 环节 | 规则 |
| --- | --- |
| 浏览 | 查看头像、名字、年龄、职业、简介和标签；左滑跳过，右滑表达兴趣。当地日期每天最多 20 位，**没有刷新或换一批**。约一半位置参考已表达的兴趣，另一半保留随机。 |
| 匹配 | 成功可即时出现、现实几天后出现或下次登录出现，按人物和情境设计；失败不提示。免费玩家当天滑完即空池，空池是付费点，见第 7 节。 |
| 聊天 | 玩家通过提供的对话／行动选项参与，无自由输入、无在线 AI 补写。**桃子主线**不靠点击快进现实等待。**普通角色**每条故事大约一百行，下一段要等玩家跟别人聊过、滑过卡、换过页面，或过几分钟。 |
| 停留／退出 | 任何阶段都可暂不回复、不推进或转去其他线，玩家也可以自己解除匹配。停留不自动判失败。**主要角色不会主动解除匹配。** 普通角色的 ghosting 只写成故事结局，人还留在消息里。 |
| 多线 | 可以同时发展多段关系。默认互不知情。跨线泄漏是随机事件：一局最多一次，且只发生在玩家已经线下见过的角色之间。见第 4.2 节。 |
| 结局 | 按角色线独立结算 HE／BE，解锁番外；一条线结束后仍可继续其他线。HE 不等于必须恋爱。 |

玩家可以拒绝所有候选人，不强迫接受某个角色。当天的人滑完后，免费玩家等到本地次日；不另写一段独身生活来填空。

## 3. 关系规则

| 阶段 | 内容与转折 |
| --- | --- |
| 相遇／尴尬期 | 破冰、日常和互相了解。默认可写非浪漫、非调情的身体吸引感。是否出现调情或恋爱氛围，**按角色分开**，见第 7 节。 |
| 朋友 | 共同经历、信任与分歧，不以暧昧替代友谊。可进入友情结局；也可在充分铺垫、双方明确表达意愿的转折事件后进入恋爱及结局，或成为炮友。 |
| 炮友 | 明确边界，描写亲密后的相处。多数角色不迅速沦陷，少数例外需人物理由；后续可改变关系或分开。 |
| 结局／番外 | 由经历、选择与双方需求共同决定，不由好感值自动升级；番外不推翻结局中的重要选择。 |

关系不是一条必须爬的梯子。同一角色可以停在朋友，可以友情结局，可以先进入生活再进入身体，也可以先进入身体再进入生活。恋爱不必经过炮友。

亲密以双方自愿、可撤回为前提；角色可以拒绝、改变主意或结束关系，拒绝不自动判为失败。**「只用下体思考」可以是公开人设或反差，不能当整个人。** 再擦边的角色也要有工作、爱好、压力和被拒后的反应。

## 4. 时间与事件

- 预约采用**玩家当地现实时间**，显示日期与时间；到点开放对应事件选项，不靠点击推进时钟。不用固定上海时间，也不让玩家另选时区。
- 开放窗口、宽限期、迟到／离线后果及可否补玩，**按角色和事件分别设计**。不设统一宽限期，也不默认所有预约都能随时补玩。
- 现实时间流逝不代表所有剧情自动推进，也不代表未操作就解除匹配。
- 每个事件至少写清：角色、关系阶段、前置条件、时间／窗口、玩家选项、后果与后续。
- 随机／快推事件仍须服从该角色自己的前期尺度和双方意愿；不能因为点得快就替人答应亲密或恋爱。关键转折与结局需要明确触发条件。
- 桃子主线的预约、错过和数周等待仍按上列现实时间规则。普通角色的章节是剧情压缩：下一段只隔一次别的操作或几分钟，不冒充按天等待，也不能用来快进桃子。

**事件样例：**朋友一起看展，被临时抓去当志愿者，负责解释一件谁也没看懂的作品。可选认真胡说、坦白不懂、去问作者；结果体现人物性格，不自动转成暧昧。

## 4.1 Dating 故事光谱

背景人物和后续专属线从下列处境里抽，不要求每人走一遍，也不把桃子改成这些戏。幽默可以尖锐，不拿水果种类本身取笑角色。

| 走向 | 写什么 | 约束 |
| --- | --- | --- |
| 纯爱小狗 | 认真、黏、愿意先进入生活 | 不是没有边界的奉献；拒绝仍有效 |
| 先生活后身体 | 朋友铺垫后再谈亲密或恋爱 | 桃子主线已有此路 |
| 先身体后生活 | 先说清炮友／FWB，再看会不会进入日常 | 要有当下同意；旧同意不顺延 |
| 暧昧拉扯 | 读已读、改约、话说一半 | 只发生在该角色被允许的前期尺度内 |
| 只用下体思考 | 把无关话题听成性暗示；约会安排围着欲望转 | 必须另有生活；被拒后有自尊，不是功能道具 |
| 遇见 FWB | 明确非排他、可停 | 不等于已经恋爱 |
| ghosting | 已读不回、匹配后消失、约好不到 | 是角色主动退出的一种写法，规则见第 7 节第 4 条；停留不等于自动失败 |
| 当小三／被当小三 | 玩家或对方另有未披露的关系 | 只走第 4.2 节那一次线下撞见；未说出口的聊天对方读不到 |
| 对方哭了 | 需求不合、被拒、发现非排他之后 | 真实失落，不是羞辱玩家或嘲笑角色 |
| 和别人官宣 | 对方或玩家把另一段关系公开 | 若涉及两条玩家线，必须来自第 4.2 节那一次泄漏 |

### 上海约会模板：咖啡、晚饭、kiss，然后 ghost

这段作为普通角色 `ghosting` 线的重点场景，优先绑定背景人物 **Leo（BG_000112，金融从业者）**，不改写桃子主线，也不代表所有上海约会或金融从业者都如此。

1. 开场通常在咖啡店。对方穿西装或衬衫，坐下没聊几句就开始讲行业、出差和最近看的项目；你端着拿铁，对方翻手机展示项目图和收益曲线，自称在 NYU 读过金融，后来却在 LinkedIn 搜不到。
2. 接着转场吃饭。餐厅难订、灯光暧昧、人均不低，菜上来先让手机吃；对方继续讲职业规划、资源和未来版图，听着厉害，却和玩家没什么关系。
3. 饭后去梧桐区或江边散步。酒意和晚风到位，两人 kiss；玩家可能以为关系终于开始推进。
4. 第二天起，回复像挤牙膏，几天后彻底安静。动态照常发，玩家消息不回；偶尔突然点一个赞，但绝不主动聊天。

文案基调可以概括为：**「上海 dating 就是咖啡、晚饭、kiss，然后 ghost。」** 这是可被人物和选择打断的故事模板，不是系统对现实上海的事实判断。

### 上海 dating 男嘉宾统一出厂指南

作为一组带有调侃口吻的普通人物写作素材，笑点落在**精心经营的松弛感，与不肯经营的关系**之间。标题沿用社交软件上的「男嘉宾」说法，水果角色仍弱化性别；这套表现可以拆开、混搭，不按物种或性别统一分配。

1. **人设三件套：**陆冲板、黑框眼镜，再加一张杯子商标朝外的手冲照。周末必发「滨江骑行＋手冲」，配文「生活需要松弛感」。照片是随手拍的，前提是重拍十二遍。
2. **经典话术：**「其实我不太相信爱情了，但遇到你有点不一样。」转头说「最近行情不好」，又不经意把副业月入十万的截图放到你面前。收益是对方的自述，截图可以缺本金、缺周期；不替人物认证财富。
3. **隐藏人设：**前任据说是「网红」，讲不出具体矛盾，但记得粉丝量。梦想是「数字游民」，目前在家炒币，电脑暂时搬不开。想画的画、想做的东西，都排在财务自由以后。
4. **最终走向：**三次约会后不再回复，公开动态继续更新：「专注自我成长，35 岁前 FIRE。」计划里排满了未来，聊天框里没有下一次。

**讽刺尾注：本批次嘉宾支持七天无理由冷淡，过期不候。** 「七天」是故事中的时间压缩，不要求玩家现实等七天；不是惩罚玩家晚回复的系统机制。

### 这单你来吧：反复逃单与 AA 翻脸（2026-11-04）

绑定 **Sherry（BG_020001，PM）**，剧情 ID 为 `bill`。创作原型是约会中只享受招待、不愿承担花销的一方。沿用水果角色弱化性别的设定，用具体行为表现「捞」：主动挑店、答应回款却不转、把追问说成小气。主页先呈现正常人的职业、书店、健身和桌游爱好，不提前贴标签剧透。

1. 从没拆封的书聊到周末咖啡，第一次见面用「手机快没电了」请玩家垫钱，说好回头转。
2. 追问转账，回一句「你还真记着啊」，再许诺「下次我来」。
3. 主动挑一家更贵的餐厅，结账时去洗手间；回来反问「还没结啊」，再次推掉买单。
4. 前两笔钱都没转，玩家在第三次见面前明确提出各付各的。对方含糊答应，到店仍把付款码推给玩家。
5. 玩家问「前两次都是我付，这次 AA 有什么问题？」或「你是不是从来就没打算买单？」，对方愤怒反驳，拿包离开。最后以消息争执或不再回复收尾。

共 8 章、3 次线下见面、10 条可终止路径。每次邀约前均可退出；第一次咖啡或第二次晚饭就追问买单，也会提前散场。故事不强迫玩家付三次钱才能退出，不接实际支付或余额系统。结局后保留匹配和记录，供玩家自己决定是否解除。

新匹配走这条线；旧 Sherry 存档继续原来的 `arcId`，保留历史消息和进度。其他角色的默认分配池保持原顺序。

### 聊天文案语气（2026-11-04）

- NPC 和玩家选项使用日常中文，允许短句、口头语、含糊和转移话题。角色可以不讲理，也可以不把自己想明白。
- 少让人物复述心理分析或关系守则。例如「我不会私下默认我们已经在一起」改为「我不跟别人说咱俩已经在一起了」；「未约定排他」改为「还没说好只跟彼此约会」。
- 吃饭、消息、工作、赶车和约时间等具体事情推动对话。留出不同人物的热情、敷衍、直球和回避，避免人人用同一种成熟咨询口吻。
- 旁白可以保留文学性，但不替角色贴现实群体标签。亲密意愿、防护、隐私和可随时停止仍需表达清楚，换说法不削弱原有条件。
- 本轮更新现有 11 套普通短篇的对白与玩家选项，并新增买单线。桃子主线及共用关系对话也调整部分措辞；主线等待、预约和分支条件沿用原逻辑。

## 4.2 谁知道什么

角色读不到别的聊天，也不默认全员知情。玩家主动说出口的内容，该角色可以知道。

跨线泄漏另外只有一种来源：**随机事件，一局最多一次。** 两名当事人都必须是玩家已经线下见过的人（约见已发生，不只是匹配或只在聊天）。事件是这两人相遇或互相认出，不是系统广播。没有第二次，也没有第三人自动听说。一局里若从未线下见过两个人，这条事件不出现。

桃子主线里，P11 仍只根据玩家实际发出的那句；不因此改成她能读其他聊天。

## 9. 随机人物生成器

制作和运行时都要能走通：**底层设定 → 同一角色的图组、简介、标签**。它服务发现页和背景快推，不代替桃子手写主线，也不把生成结果直接当成第二条完整专属线。

3. **一致性校验：**同一角色的轮廓、语言、果柄／叶片、五官、四肢、配色和画风必须对得上；标签语气要贴原型。

**验证标准**

- 设定与公开面板解耦：内部有动机和压力，主页可以表演松弛、条件或欲望。
- 默认图组：1 张主照片建立第一印象，再加 2 张生活／情境照。这是生成器的默认包，不是产品规定人人必须三张；需要反差或群像可以加减。
- 标签：角色自填的公开标签，可混一条系统判定标签；不声称看穿玩家。
- 支持锁定设定、只重抽图片或只重写文案。
- 生成方式未定：规则抽取设定再配图文、模板组合、或生成模型辅助。未定之前，运行时继续用手写库和现有图，不把未接入的生成器当验收。
- 生成出的人物进入候选池后，遵守每天 20 张、不刷新、已匹配不再抽到；聊天仍走快推，尺度跟该人的关系需求走。

### 10.2 角色与画风一致性

**Ce 本轮要求：**提高一致性。后续角色图按以下规范制作与检查；这些是制作要求，不表示上一轮候选已通过或已定稿。

- **基础造型保持：**水果本体＋简化四肢，不增加独立人类头部或人类躯干；全部成年。水果类别、主轮廓、果柄／叶片、五官布局、四肢比例与基础配色，构成同一角色的识别锚点。
- **先确认一个角色基准：**每位先选择或修订一张可接受的基准图，再把它作为该角色后续照片的身份参考；不同照片不各自从纯文字重新发明角色。未经选择的候选不是已锁定身份。
- **同一套视觉语言：**整套资料照统一二维插画方向、线条粗细、五官简化程度、色彩饱和度、材质颗粒与光影复杂度。具体风格仍需选择，不能把粗线平涂、柔和水粉、写实人脸等互不兼容方案混作同一成品组。
- **允许变化的内容：**场景、镜头、动作、表情和有理由的换装随照片套路变化；同一件衣服与同一包具的颜色、结构、补丁位置应延续。道具与生活方式应能与角色设定衔接；刻意摆拍的反差也需可解释。
- **同一角色跨图核对：**并排检查果形、五官位置、叶片／果柄、肢体比例与配饰；不能只靠同一种水果或同色衣服认人。换角度、戴墨镜、手机挡脸或背影照，也应靠其余锚点保持身份。
- **以资料页裁切检查：**同一用途统一画幅与裁切逻辑，兼顾手机小图识别；照片可以是近景、半身、全身或远景，不强制全部白底全身。群像的难辨认可以是刻意套路，其余照片不应因生成漂移而认不出号主。
